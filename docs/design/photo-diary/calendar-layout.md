## 최신 추가 규격 — 밝은 면을 이미지 하단 끝까지 연장

- 상단 장식선 아래의 밝은 달력 면을 좌우 끝과 이미지 맨 아래 끝까지 하나로 이어지게 만든다. 하단 탭 뒤에도 같은 면을 유지한다. 달력 면 아래에 바닥·배경 장면·가로 경계선이 다시 나오면 안 된다.
- 830×1896 기준 밝은 면은 y=790부터 y=1896까지 이어진다. 상단 장식만 유지하고 좌우·하단 테두리는 제거한다. 연월·요일·날짜의 앱 좌표와 탭 안전 여백은 공통 JSON을 따른다.
- 과거의 하단 296px 바닥 배경 지시는 폐기한다. 해당 구간도 같은 밝은 달력 면으로 채운다.

## 최신 추가 규격 — 상단 장식만 유지

- 좌우 세로 테두리와 하단 가로 테두리를 모두 제거한다. 선·레일·마감선·테두리 그림자도 포함한다. 상단 장식선만 장면별 재료와 형태로 디자인한다.
- 상단 장식은 원본 830×1896 기준 y=760–784에 두고, 밝은 빈 면은 y=790 이전에 시작해 연월·양쪽 화살표·요일·마지막 날짜 영역까지 이어진다. 앱 month/weekdays/grid 좌표는 공통 JSON을 사용한다.
- 밝은 면은 좌우 끝까지 이어진다. 배경도 상태 표시줄 뒤부터 하단 탭 아래 화면 끝까지 채운다. 하단 배경 구간 296px를 유지한다.
- 아래에 남은 양옆 프레임 지시와 기존 승인 이미지의 세로 레일은 이 추가 규격으로 대체한다. 생성 시안은 좌표 측정 전까지 규격 통과로 보고하지 않는다.

## 현행 규격 — 2026-11-12 빈 면 v2

최신 승인 기준은 [승강장 빈 면 이미지](references/platform-open-panel-approved.png)와 [좌표 JSON](city-calendar-template.json)의 artwork 정책이다. 이 절은 아래의 과거 격자·요일칸 인쇄 지시보다 우선한다.

- 일러스트는 상태 표시줄 뒤부터 하단 탭 아래 화면 끝까지 채운다. 연월과 양쪽 화살표 전체가 밝은 사각 면 위에 올라오도록 윗장식을 배치한다. 이 면은 요일을 지나 마지막 주의 날짜·사진까지 이어진다.
- 그림에는 날짜 격자, 요일 7칸, 월·연도 영역 바로 밑 가로 구분선, 판 맨 아래 가로 테두리를 넣지 않는다. 월·요일·날짜를 넣을 공간은 하나로 이어진 깨끗한 빈 면으로 남긴다.
- 상단 장식과 양옆 프레임은 각 일러스트의 장소·행동·재료에 맞춰 새로 설계한다. 승강장 금속 프레임을 다른 장면에 복제하지 않는다. 색만 바꾼 결과는 허용하지 않는다. 예: 도예는 유약·도자 마감, 세탁소는 천·바느질, 미술관은 전시 액자 소재. 장식이 앱 콘텐츠 영역 안으로 들어오면 안 된다.
- 기존 830×1896 캔버스, 판 영역 [21,798,790,802], 아래 배경 296px 및 앱 month/weekdays/grid 좌표는 유지한다. 날짜 7열×6행은 앱의 보이지 않는 배치 좌표이며 이미지에 인쇄하지 않는다. monthPlate/weekdayPlate는 과거 측정값이다.
- 승인 이미지는 시각 디자인 기준이다. 생성 이미지의 실제 크기·좌표가 이 JSON과 일치한다고 측정·검증한 것은 아니다.
- 기존 제작기와 verify-city-calendar-preview.cjs는 인쇄된 칸 경계를 만들거나 검사하는 구형 규격이다. 빈 면 v2에 맞춘 수정 전에는 신규 제작·통과 보고에 사용하지 않는다. 앱 좌표와 7개 화면의 탭 간격은 계속 검증해야 한다.

## 화면 안전 영역

- 배경은 화면 끝까지 이어져도 되지만 날짜, 요일, 사진, 버튼은 노치와 하단 탭을 침범하지 않는다.
- 메인 화면은 실제 측정된 하단 탭 높이와 12pt 간격을 예약한다. 측정 전에도 탭 행 56pt + 하단 안전 영역 + 상단 패딩 8pt를 예약해 첫 프레임의 이동을 막는다.
- 달력 전체 구성(배경의 표 포함)을 예약 영역 위의 높이에 맞춘다. 숫자만 위로 옮기거나 배경과 다른 비율로 배치하지 않는다.
- 탭 아래의 장식 배경에는 날짜나 터치 영역을 넣지 않는다.
- 캘린더 템플릿 목록은 일반 안전 영역을 사용한다. 메인 전체 화면 헤더 배치를 재사용하지 않는다.

## 신규 일러스트 캘린더의 공통 골격

앱에서 내려받은 시티 애니메이션 **06-angry-email**의 사무실 장면을 기준으로 삼는다. 서버에서 재다운로드한 WebP는 830 × 1896 px이고 SHA-256은 `51d6c41f0d60983b21e186986aa687de100059dfada9991f8fe662ffa9357027`이다. 같은 이름의 초기 제작 폴더에는 941 × 1672 px 시안도 있으므로 해시로 기준 파일을 식별한다.

제작기와 검증기는 [공통 좌표 JSON](city-calendar-template.json)을 읽는다. [빈 SVG 골격](city-calendar-template.svg)은 디자인 도구에서 원본 크기로 열 수 있다. 좌표의 원점은 원본 왼쪽 위이며 모든 값은 px이다.

| 영역 | 왼쪽 x | 위쪽 y | 너비 | 높이 |
|---|---:|---:|---:|---:|
| 캔버스 | 0 | 0 | 830 | 1896 |
| 달력판 외곽 | 21 | 798 | 790 | 802 |
| 월·연도 표면 | 44.46 | 818 | 741.07 | 81 |
| 월·연도 앱 텍스트 영역 | 44.46 | 799.88 | 741.07 | 91.84 |
| 요일 표면 | 44.46 | 912 | 741.07 | 43 |
| 요일 앱 텍스트 영역 | 44.46 | 906.52 | 741.07 | 53.32 |
| 날짜 격자와 터치 영역 | 44.46 | 968.74 | 741.07 | 616.20 |

- 장면은 캔버스 전체 폭을 채운다. 판 윗변은 y=798, 밑변은 y=1600이다. 밑변 아래 배경 296px는 하단 탭이 올라오는 자리다. 실제 화면의 여백은 화면 크기, 안전 영역, 탭 실측 높이에 따라 달라진다.
- 월·연도 표면과 요일 표면의 높이는 기준 파일의 인쇄된 테두리를 측정한 값이다. 텍스트 사각형은 시티 테마의 앱 보정값이다. 두 종류의 좌표는 용도가 다르다.
- 앱은 보이지 않는 날짜 영역을 **7열 × 6행**으로 배치한다. 이미지에는 날짜 칸이나 요일칸을 인쇄하지 않는다. 한 날짜 칸의 너비는 741.07/7, 높이는 616.20/6이다. 월·요일·날짜·사진·이벤트·탭은 앱에서 올린다. 각 칸은 앱 텍스트가 선명하게 보이도록 비우고, 선 색은 테마 재질과 어울리는 진한 색으로 정한다. 검정으로 통일하지 않는다.
- 모든 테마에서 정면 배치, 장면과 달력이 만나는 높이, 월·요일·날짜의 중심, 달력판 밑변을 고정한다. 재질, 테두리, 바느질, 타일, 부착 장식은 장면에 맞춰 별도로 구성한다.
- 이 골격은 **위치와 앱 데이터 슬롯만 고정**한다. 시각 스타일을 공통 판으로 복제하라는 뜻이 아니다. 테마마다 장면의 장소·행동·주요 재료를 반영해 프레임 형태, 표면 재질, 월/요일 판의 장식, 날짜 칸 테두리와 안쪽 표현을 새로 설계한다. 팔레트만 바꾸거나 동일한 판에 테두리색만 바꾼 결과는 통과시키지 않는다.
- 인접 테마를 포함해 달력 스타일이 반복되지 않는지 contact sheet에서 비교한다. 각 달력은 작은 썸네일에서도 장면에 맞는 재질과 프레임이 읽혀야 한다. 장식은 텍스트 슬롯과 날짜·사진·이벤트가 들어갈 칸 안쪽을 침범하지 않는다.
- 기존 첫 3개 테마처럼 장면 재료와 조형을 살린 스타일을 기준 삼되, 그 외 테마에 첫 3개의 프레임을 복제하지 않는다. 극장에는 벨벳/필름, 도자 작업에는 유약/도자 테두리, 수영장에는 타일 등 장소별 소재를 선택한다.
- 배경과 앱 콘텐츠에 동일한 `fitCalendarArtwork` 변환을 적용한다. 렌더링 후 PNG에서 빈 칸과 경계를 검사하고, 골격의 마지막 행과 외곽 밑변을 기준 파일과 같은 화면 좌표로 투영한다.

## 검증

- 자동 화면 기하 검사는 모든 테마를 다음 7개 세로 화면 크기(pt)에서 검사한다: 320×568, 375×667, 375×812, 390×844, 393×852, 430×932, 440×956.
- 2026-11-10 기준 50개 테마 × 7개 화면 크기, 총 350건의 검사가 모두 통과했다. 결과 원본은 `output/calendar-v8-fullscreen/viewport-audit.json`이며, 검사 스크립트는 `scripts/audit-calendar-viewport.cjs`다.
- 이 자동 검사는 배경 전체 채움/비율 유지, 월·요일·격자의 안전 영역 겹침, 사진과 날짜 간 겹침, 6행 구성을 확인한다. 기준 좌표를 적용한 달력판 바깥 밑변과 하단 탭 윗면 사이 간격도 비교한다. 태블릿 및 가로 화면과 실제 기기의 렌더링은 별도 시각 검증 대상으로 둔다.
- 화면 검증은 이미지별 SHA-256 manifest를 만들고 100개 테마 × 7개 화면 크기, 총 700건의 기하 검사를 수행한다. 새 배치의 결과는 산출 폴더 `verification.json`에 기록한다.
- 2026년 11월처럼 6주가 필요한 달, 2028년 2월 윤년, 28/30/31일 달을 검사한다.
- 마지막 주 날짜와 일기 사진, 일정 점, 터치 영역이 탭 상단보다 위에 있어야 한다.
- 42개 날짜 칸 모두에서 두 자리 날짜 숫자, 사진, 일정 표시가 서로 겹치지 않아야 한다. 요일 중심은 각 열과 일치하고 표 선이 글자나 사진을 통과하지 않아야 한다.
- 320×568pt 화면에서 실제 `calendarCellContents` 배치를 얹어 날짜 숫자와 사진/일정 표시가 42개 모든 칸 안에 들어가는지 확인한다. 6주가 필요한 달에서도 일곱째 주를 추가하지 말고 기존 6행에 정확히 배치한다.
- 코드 좌표 검사는 실제 렌더링 확인을 대체하지 않는다. 배포 전 대표 화면 크기의 시뮬레이터/기기 스크린샷을 확인한다.


## Published original artwork — 20261109-grid-v3

Five city backgrounds were edited as actual images, encoded as WebP, and published to `character-illustrations/calendar-themes/20261109-grid-v3/`. The walking background and paper/leaf sprites are unchanged compatibility assets. All 18 uploaded files were downloaded again and matched the SHA-256 manifest in `calendar-grid-v3-manifest.json`.

The authenticated `calendar-theme` function serves this revision when requested. Older clients continue receiving their original revision to avoid combining old hit areas with new artwork. Updated clients migrate previously installed v2 themes to the new files and remove each obsolete local theme only after successful download. Dates remain dynamic app text; the artwork contains blank cells, never a fixed month.

Stair artwork now contains six actual rows. Office pointer no longer overlaps cells. Frame coordinates were measured against the edited images, not merely assumed from generation prompts. Device visual verification is still required; geometry and cache migration tests do not replace simulator checks.

- 100개 모두 `p5-01`–`p5-100` 원본 장면에서 다시 조판한다. 한 번에 최종 교체하기 전 처음 10개를 스타일과 장면 크롭 확인용으로 렌더링한다.
- 산출은 830 × 1896px PNG다. 달력판 `[21, 798, 790, 802]`, 월·연도판 `[44.46, 818, 741.07, 81]`, 요일판 `[44.46, 912, 741.07, 43]`, 날짜 격자 `[44.46, 968.74, 741.07, 616.20]` 좌표를 그대로 쓴다. 달력판 아래 y=1600–1896의 배경은 탭이 놓이는 고정 296px 구간이며, 달력판·마지막 행을 이 구간 쪽으로 옮기지 않는다.
- 각 장면은 기존에 인쇄된 달력판을 덮어 공통 골격에 맞춘다. 장면의 인물 머리와 핵심 동작이 판에 잘리지 않도록 위쪽 장면 크롭을 확인하고, 아래 바닥 조각은 탭 영역까지 자연스럽게 이어 붙인다. 배경 종횡비는 유지한다.
- 고정하는 것은 달력판 좌표, 월·요일·날짜 슬롯, 선명도와 탭 간격이다. 테마마다 프레임 조형, 재질 패턴, 판 표면, 칸 모서리·이중선·스티치·장식과 선 색을 장면에 맞춰 바꾼다. 팔레트만 바꾼 결과 또는 같은 셀·프레임 표현의 반복은 통과시키지 않는다.
- 연도·월, 요일 글자, 날짜 숫자, 사진, 일정 표시, 탐색 화살표는 PNG에 인쇄하지 않고 앱에서 표시한다. 42개 날짜 칸은 날짜·사진·일정을 넣을 수 있게 안쪽을 비워 두고, 장식과 질감은 이 영역을 침범하지 않는다.
- 제작은 `scripts/compose-everyday-cinema.cjs`와 `scripts/rasterize-everyday-cinema.cjs`를 사용한다. 7개 화면 크기 검증은 `scripts/verify-city-calendar-preview.cjs`로 실행한다. PNG 픽셀 경계와 빈 칸을 확인한 뒤 100개 테마 × 7개 화면 크기 총 700건을 기록한다.
- 인접 테마를 포함한 contact sheet에서 실제 재질·프레임·칸 표현이 구분되는지 검토한다. 첫 10장과 전체 비교 시트를 최종 폴더에 manifest 및 검증 보고서와 함께 보관한다.

## 2026-11-12 스타일 재작업 지시

이전 11–100 결과는 공통 선형 판과 옅은 셀색을 반복하고 포인트 색만 바꾼 것으로 판정했다. 이를 승인된 스타일로 간주하지 않는다. 재작업할 때 앞 절의 스타일 고유성 규칙을 우선한다. 각 테마는 장면별 별도 스타일 보드를 만들고, 고정 골격을 얹은 뒤 작은 썸네일 비교로 스타일 차이를 확인한다. 새 재작업 1–3을 먼저 확인 기준으로 삼고, 전체 생성은 프레임/재질/칸 표현이 실제로 달라지는 것을 확인한 제작기로 이어간다.

## 2026-11-13 Everyday Cinema 상단 장식·연속 빈 면 100장 배포

이 절이 위의 격자·프레임·296px 바닥 배경 기록을 대체한다. 현행 규격은 `city-calendar-template.json`과 `calendar-large-board-production.md`를 따른다. 830 × 1896px 캔버스의 상단 장식은 `[0,760,830,24]`, 연속 빈 면은 `[0,784,830,1112]`이다. 날짜 격자, 요일칸, 월판 구분선, 좌우·하단 테두리, 하단 바닥 장면을 인쇄하지 않는다. 월·요일·42개 날짜와 사진은 앱이 공통 좌표로 표시한다.
