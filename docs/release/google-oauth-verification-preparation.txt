SCOPE JUSTIFICATIONS (submission draft)
calendar.events.readonly:
Daylight displays events from the signed-in user's primary Google Calendar alongside their photo diary. After the user explicitly connects Google Calendar, the app reads events within the displayed date range and shows event titles, dates, times and all-day status. It does not create, edit or delete Google Calendar events. Read-only access is necessary to display existing private events; public-calendar access cannot provide this functionality.

tasks.readonly:
Daylight displays dated Google Tasks alongside calendar events in the diary. The app reads the user's task lists and tasks with due dates in the displayed range. It displays task titles and due dates, including completed tasks when returned by Google. It does not create, edit, complete or delete Google Tasks. Read-only access is necessary to display the user's existing tasks.

drive.appdata:
The user can back up selected diary dates and associated media to Daylight's private application data folder in their own Google Drive and later restore those backups. Daylight creates, reads and deletes its own backup files. It does not request access to arbitrary Drive documents. This permission is requested through the backup connection flow.

IDENTITY
Google Sign-In identifies the connected Google account. The app uses the account email to display and validate the calendar/backup connection. Basic identity scopes are supplied by the Google Sign-In SDK.
