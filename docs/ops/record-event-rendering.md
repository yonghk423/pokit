# 기록과 이벤트 표시 최적화

갱신일: 2026-11-15

## 기록

`HeroInlineNote.tsx`는 초기 WebView 준비 및 선택한 글꼴의 첫 레이아웃 동안 정적인 스켈레톤을 표시합니다. 비어 있는 기록의 입력 안내는 초기화 완료 이후에 보여줍니다. WebView 오류에는 다시 불러오기 동작을 제공하고, iOS WebView 프로세스 종료 시 문서를 다시 준비합니다.

본문은 삽입 그림 파일 전체를 기다리지 않고 초기화합니다. 삽입 그림 ID의 자리는 유지한 채 고정 크기 이미지 슬롯에 나중에 파일을 채웁니다. 같은 그림이 여러 번 등장하면 해당 ID의 에셋을 한 번 요청하고 모든 슬롯에 반영합니다. 에셋 준비 Promise는 실행 세션에서 재사용합니다.

HTML 초기화는 DocumentFragment를 이용해 DOM에 한 번 반영합니다. 초기화 직후 전체 내용을 다시 직렬화해 저장하던 불필요한 작업을 제거했습니다. 실제 사용자의 편집 내용은 기존처럼 입력 시 저장합니다. 초기화가 끝나기 전에는 WebView를 숨겨 글꼴 전환이나 부분 배치를 노출하지 않습니다.

`HeroInlineNote`의 memo 처리와 부모 콜백 안정화로 다른 이벤트 입력 상태가 바뀔 때 기록 WebView 하위 트리를 반복해서 렌더링하지 않도록 했습니다. 같은 날짜에서 기록·캘린더·이벤트 탭을 이동할 때 기존 기록 인스턴스를 유지합니다. 날짜 변경이나 부모 화면 전환으로 컴포넌트가 제거된 경우에는 WebView를 다시 생성합니다. 무제한 WebView 풀을 만들지 않습니다.

## 이벤트

- 이벤트는 첫 화면을 그린 뒤 idle 작업에서 읽고, 준비 중에는 스켈레톤을 표시합니다.
- 날짜가 바뀌면 이전 날짜의 대기 작업을 취소합니다. 준비 전에는 새 이벤트 입력·저장을 막아 이전 배열로 덮어쓰지 않습니다.
- 개인 이벤트 목록을 ScrollView 전체 렌더링에서 FlatList로 바꿨습니다. 초기 8개, 추가 배치 8개, windowSize 5입니다. 긴 제목은 줄바꿈하고 스크롤로 끝까지 볼 수 있습니다.
- 이벤트 행은 memo 처리하며, 삭제 확인 후 최신 목록을 기준으로 제거합니다.
- 연동 캘린더는 처음 데이터를 가져오는 동안 일정이 없는 열에 스켈레톤을 표시합니다. 기존 일정이 있으면 새로고침 중에도 유지합니다. 연동 캘린더의 두 열 목록 전체 가상화는 이번 변경에 포함하지 않습니다.

## 검증과 한계

새 회귀 검사 6개에서 스켈레톤 전환, 그림 로딩 지연과 무관한 본문 초기화, 약 9만 자 기록 및 반복 그림 ID 보존, 재초기화 시 중복 방지, 이벤트 1,000개 중 최초 8개 렌더링, 이전 날짜 로딩 취소를 확인했습니다. iOS production export도 성공했습니다.

이는 단말 성능 측정값이 아닙니다. 실제 기기에서 긴 기록의 최초 진입·날짜 이동·스크롤·편집 저장, 이벤트 다수의 스크롤과 삭제, WebView 재시작 후 복원 확인이 필요합니다. 긴 텍스트 자체의 네이티브 레이아웃 비용과 최초 글꼴 로딩 시간은 여전히 존재합니다.
