# 유료 이미지 자산 전수 점검 — 2026-11-19

확인 결과, 정적 유료 상품 이미지는 모두 실제 WebP지만 **모든 유료 기능이 ‘경량 WebP 썸네일 + 별도 고해상도 WebP 원본’ 구조로 통일된 상태는 아니다.**

## 확인 방법과 범위

- 현재 `proDiaryCatalog`와 실제 Pro 판정 함수에 등록된 다이어리 상품 90종. 현재 무료인 Polaroid Now와 Leica SOFORT 2, 무료 기본 장식은 유료 수량에서 제외했다.
- 앱이 제공하는 유료 일러스트 캘린더 8팩, 서버 매핑의 현행 테마 320개.
- 별도 시티팝 장면 팩은 현재 클라이언트가 사용하는 p7-01 한 장과 미리보기 경로를 점검했다.
- 유료 필름 12종은 정적 상품 이미지가 아니라 사용자 사진에 적용하는 처리 코드이므로 썸네일 생성 방식과 결과 형식을 코드에서 점검했다.
- 인증된 Supabase 대시보드에서 현행 서버 파일을 ZIP으로 내려받아 검사했다. 확장자뿐 아니라 RIFF/WEBP 시그니처, Sharp 디코딩 형식, 실제 픽셀 크기와 바이트 수를 확인했다. 검사용 원본은 `output/paid-image-audit-20261119/remote/`에 보관했다.
- 이번 요청에서는 상품 파일이나 앱 동작을 변경하지 않았다. 추가한 것은 점검 스크립트와 보고서다.

## 다이어리 상품 90종

썸네일 **108개**, 서버 원본과 사진틀 조각 **156개**를 모두 확인했다. 누락 0개, WebP가 아닌 파일 0개. 모든 상품의 주 원본은 해당 썸네일보다 큰 픽셀 크기를 가진다. 썸네일과 실제 적용 경로는 분리되어 있다.

| 구분 | 상품 수 | 실제 적용 파일의 해상도 |
| --- | ---: | --- |
| 집게 | 18 | 긴 변 1536px |
| 카메라 | 11 | 긴 변 1536px |
| 휴지통 | 18 | 빈 상태·찬 상태 모두 긴 변 1536px |
| 포토월 | 11 | 가로 2072–2131px |
| 날짜표 | 10 | 가로 850–900px |
| 탭 장식 | 9 | 가로 850px |
| 사진틀 | 6 | 전체 미리보기 원본 400×500px; 실제 적용은 8개 조각 합성 |
| 참·메모지·포켓·책갈피·사진 코너·핀 | 7 | 긴 변 910px |

최근 고해상도로 교체한 집게·카메라·휴지통 47종과 포토월 11종, 총 58종은 1536px 이상 원본이다. 나머지 32종은 기존 500–910px급 규격이다. 따라서 모든 상품이 1536px 이상이라고 보고할 수 없다. 작은 화면 장식에는 850–910px이 충분할 수 있으므로 픽셀 수만으로 선명도 불량이라고 단정하지 않았다.

사진틀은 `HeroPrintBorder.tsx`에서 전체 400×500 이미지가 아니라 모서리 80×80px, 위·아래 240×80px, 좌우 80×340px 조각을 합성한다. 모서리는 화면에서 최대 24 단위로 표시되므로 3배 밀도 72px를 넘는다. ‘전체 사진틀 원본이 1536px가 아니다’와 ‘실제 표시가 흐리다’는 구분해야 한다.

썸네일 용량은 **2516–112972바이트**다. 날짜표·탭·사진틀 등은 대략 2.5–19KB, 포토월은 13.8–24.1KB, 집게는 11.6–34.1KB, 카메라는 37.8–79.8KB, 휴지통은 31.5–113.0KB다. 라탄 휴지통 두 썸네일은 각각 112972/107222바이트(약 110.3/104.7KiB)로 다른 썸네일보다 무겁다. 그 밖의 썸네일은 모두 100KiB 이하다. 긴 변 512px를 조금 넘는 세로형 썸네일도 있으나 가로 400px 파생 파일이며, 원본을 그대로 넣은 것은 아니다.

세부 기록: [diary-assets.json](diary-assets.json). `fullImageUnder1024`는 긴 변 1024px 미만 목록이며, 표시 품질 불량 판정이 아니다. `largePreviews`의 기계적 기준은 100KiB 초과 **또는** 긴 변 512px 초과다.

기본형 유료 집게 12종·휴지통 9종·카메라 2종은 `diaryImage(..., fallback)`으로 다운로드 원본을 우선 사용하지만, 해당 캐시가 없으면 번들 미리보기로 표시하는 경로도 있다. `chooseItem`은 스토어에서 적용할 때 원본을 다운로드하며, 이 기본형 23종의 표시 컴포넌트 자체에는 자동 재다운로드 로직이 없다. 따라서 캐시가 비었거나 다운로드 버전이 바뀐 기존 선택 항목에 대해 ‘항상 고해상도로 표시된다’까지 보장하는 구조는 아니다. 테마형 장식은 `useDiaryTheme`의 설치 효과를 통해 다운로드를 요청한다.

## 별도 유료 장면 팩

`heroPremiumPack.ts`가 현재 사용하는 p7-01은 **720×960px WebP, 216880바이트**다. 서버 `character-pack`의 preview와 download가 모두 `protagonist-7/card-960` 경로를 사용한다. 따라서 이 팩에는 별도의 경량 썸네일이 없으며 최근 1536px급 장식 원본과도 규격이 다르다. 다운로드 폴더의 이름만으로 1536px급이라고 판정하지 않았다.

## 유료 필름 효과

유료 12종을 포함한 필름 목록은 `HeroPolaroidProcessor.tsx`에서 사용자 사진으로 미리보기를 즉석 생성한다.

- 필름 썸네일: **96×96 JPEG**, `thumb.toDataURL('image/jpeg', 0.85)`.
- 필름 보정 미리보기: 긴 변 최대 600px PNG.
- 보정 결과: 긴 변 최대 2048px PNG.
- 사진틀을 포함한 저장·공유 결과도 `HeroPolaroidExport.tsx`에서 PNG로 캡처한다.

이는 서버의 정적 유료 WebP 자산과 다른 처리 경로다. 따라서 **‘모든 썸네일은 무조건 WebP’ 기준에는 필름 썸네일이 명확한 예외**다. 출력 사진의 PNG 형식은 사용자 저장·공유 결과이므로 상품 썸네일 형식과 구분했다.

## 남아 있는 차이

1. 필름 썸네일은 JPEG이므로 WebP 기준으로 통일되지 않았다.
2. 캘린더 개별 테마 목록과 별도 장면 팩은 경량 썸네일 파일이 분리되어 있지 않다.
3. 다이어리 장식 32종은 최근 1536px급 교체 대상이 아니며 기존 해상도를 유지한다. 작은 장식과 조각 합성 프레임의 용도를 고려해야 한다.
4. 라탄 휴지통 썸네일 2개와 Everyday Cinema 팩 표지는 다른 미리보기보다 추가 경량화 여지가 있다.

재검사: `node scripts/audit-paid-image-assets.cjs` (검사용 서버 원본이 위 보관 경로에 있어야 한다).
