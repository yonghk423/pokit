# Pokit 기획서

Pokit은 하루의 계획을 시간 블록으로 구성하고, 실행 중에는 세션 화면에서 현재 플로우에만 집중하도록 돕는 앱입니다.  
이 문서는 현재 제품 방향에 맞춰 기능 목표, 도메인 모델, FSD 구조, 상태/저장 전략을 정리합니다.

---

## 1. 제품 방향

### 1.1 목표

- 사용자가 하루 계획(`day-plan`)을 시간대별 블록으로 빠르게 구성한다.
- 각 블록을 실제 실행 세션으로 전환해 진행도와 남은 시간을 확인한다.
- 실행 경험의 중심을 앱 내부 `activity-session` 화면에 둔다.
- 서버 없이 로컬 저장소 기반으로 안정적으로 동작하는 개인 플로우 도구를 지향한다.

### 1.2 현재 스코프

- **핵심 포함**
  - Day Plan 작성/수정
  - 세션 시작/일시정지/재개/완료
  - 진행도, 남은 시간, 다음 블록 반영
  - 설정 페이지와 카테고리별 목표 상세 설정
- **현재 제외**
  - Live Activity를 제품 핵심 경험으로 강제하는 요구사항
  - Android 잠금화면 중심 UX

---

## 2. 핵심 사용자 시나리오

### 2.1 오늘 계획 생성

1. 사용자는 `day-plan` 화면에서 시간 블록과 플로우를 배치한다.
2. 블록별 시작/종료 시각을 확인하며 하루 흐름을 완성한다.
3. 저장 후 오늘 계획이 즉시 반영된다.

### 2.2 세션 실행

1. 사용자는 오늘 계획에서 현재 블록을 시작한다.
2. `activity-session` 화면에서 현재 플로우, 남은 시간, 진행도를 확인한다.
3. 필요 시 일시정지/재개/완료/건너뛰기를 수행한다.
4. 상태 변경은 도메인 스토어를 기준으로 즉시 동기화된다.
5. 블록 완료 시 다음 블록 또는 종료 상태로 전환된다.

### 2.3 목표 상세 설정

1. 사용자는 카테고리별 목표 상세 설정 화면으로 진입한다.
2. 카테고리 특화 옵션(예: 물, 독서, 복약 등)을 조정한다.
3. 저장 시 해당 목표 설정이 Day Plan/세션 표시 규칙에 반영된다.

---

## 3. 도메인 모델

핵심 타입과 규칙은 `src/entities`에서 관리한다.

- `DayPlan`
  - 하루 계획의 기준 엔티티
  - 블록 순서, 시각, 연결된 목표/카테고리 정보 포함
- `DayPlanBlock` (또는 동등 개념)
  - 특정 시간 구간의 실행 단위
  - 시작/종료 시각, 상태, 우선순위/카테고리 정보를 가짐
- `Session` 관련 상태
  - 실행 중 여부, 일시정지 상태, 진행률, 남은 시간 계산 정보
- `GoalCategory` 설정
  - 카테고리별 UI/행동 규칙(물, 독서, 복약, 금식, 기타 등)

도메인 로직은 React 컴포넌트와 분리하고, 가능한 한 순수 함수/스토어 액션 중심으로 유지한다.

## 4. 아키텍처 원칙 (FSD)

### 4.1 레이어

Pokit은 아래 레이어를 따른다.

- `src/application` (app 레이어)
- `src/pages`
- `src/widgets`
- `src/features`
- `src/entities`
- `src/shared`

의존성은 상위 레이어에서 하위 레이어로만 허용한다.

### 4.2 책임 분리

- `application`
  - 앱 부트스트랩, 전역 하이드레이션, 전역 연결 로직
- `pages`
  - 라우트 단위 화면 배선 및 조합
- `widgets`
  - 여러 feature/entity를 조합한 화면 블록
- `features`
  - 유즈케이스 단위 동작(세션 제어, 알림 스케줄링 등)
- `entities`
  - 도메인 타입, 규칙, 스토어, 계산 로직
- `shared`
  - 범용 UI, 유틸, 저장소 래퍼, 테마

### 4.3 네이밍/구조 규칙

- 세그먼트는 `ui`, `model`, `lib`, `api`, `config` 중심으로 구성한다.
- 같은 레이어 내 서로 다른 슬라이스 직접 import를 피한다.
- 공통화가 필요하면 `entities` 또는 `shared`로 승격한다.

---

## 5. 상태 관리 (Zustand)

### 5.1 원칙

- 여러 화면에서 공유되는 상태는 zustand 스토어를 사용한다.
- 비즈니스 로직은 컴포넌트보다 스토어 액션/셀렉터에 둔다.
- 시간 계산은 절대 시각 기반 계산을 우선한다.

### 5.2 스토어 위치

- 도메인 전역 상태: `src/entities/<domain>/model/*Store.ts`
- 기능 전용 상태: `src/features/<feature>/model/*Store.ts`

### 5.3 상태 전이 규칙

- 세션 이벤트(`start/pause/resume/finish/skip`)는 도메인 상태를 먼저 갱신한다.
- 화면은 스토어 상태를 구독해 렌더링만 담당한다.
- 앱 재진입 시 저장된 상태를 기준으로 세션을 복원한다.

---

## 6. 데이터 영속화 (LocalStorage)

### 6.1 기본 전략

- LocalStorage를 1차 저장소로 사용한다.
- 스토어가 단일 진실 원천(SSOT)이며, 저장소는 영속화 계층 역할만 수행한다.
- 컴포넌트에서 `localStorage`를 직접 호출하지 않는다.

### 6.2 저장 모듈

- 공용 저장소 모듈: `src/shared/lib/storage`
- 도메인별 로드/세이브 헬퍼를 통해 타입 안정성을 유지한다.

### 6.3 키 원칙

- `pokit:*` 네임스페이스를 사용한다.
- 저장 구조는 엔티티 타입과 동일한 형태를 유지한다.
- 마이그레이션이 필요하면 버전 필드를 통해 점진적으로 처리한다.

---

## 7. UX/카피 원칙

### 7.1 사용자 대면 문구

- 앱 이름 `Pokit`을 제외한 UI 문구는 한글을 기본으로 사용한다.
- 사용자 대면 용어는 `플로우`를 기본 용어로 통일한다.

### 7.2 화면 디자인

- 카드 기반 레이아웃으로 현재 상태를 빠르게 파악할 수 있게 구성한다.
- 진행 정보는 프로그레스 바와 수치 텍스트를 함께 제공한다.
- 목표 상세 설정 화면 배경은 단순 평면 구성으로 유지하고 과한 장식 요소는 피한다.

---

## 8. 기술/개발 운영 메모

### 8.1 Expo CLI 정책

- 에이전트는 사용자 명시 요청 없이 Expo CLI 명령을 실행하지 않는다.
- `expo prebuild`는 영향도가 크므로 기본적으로 자동 실행하지 않는다.

### 8.2 iOS 실행 주의

- Xcode 실행 스킴은 일반 개발 시 `Pokit`(메인 앱)를 사용한다.
- `PokitLiveActivity` 스킴은 확장 디버깅 목적일 때만 사용한다.

---

## 9. 확장 로드맵

- Day Plan 자동 추천(시간대/카테고리 기반) 고도화
- 세션 완료 기록 기반 회고/통계 화면 강화
- 알림 품질 개선(시작 전 리마인드, 미완료 후 후속 안내)
- 카테고리별 세션 경험 고도화(독서/물/복약 등)

Pokit은 잠금화면 연동 여부와 무관하게, 앱 내부 세션 경험을 안정적으로 유지하면서 점진적으로 확장한다.
