# pokit 기획서

**명칭:** 사용자에게 보이는 앱 정식 명칭은 **POKIT**. 저장소·패키지·LocalStorage 키·문서 등 프로젝트 내부 식별자는 **pokit**(소문자)을 쓴다.

pokit은 하루 일과를 **시간대별 블록 배치가 아니라**, **우선순위에 따라 정한 태스크(플로우)만** 순서대로 진행하도록 돕는 앱입니다.  
떠오르는 할 일은 **빠른 메모**로 바로 적어 플로우로 저장할 수 있으며, 실행 중에는 세션 화면에서 현재 플로우에만 집중할 수 있습니다.  
이 문서는 현재 제품 방향에 맞춰 기능 목표, 도메인 모델, FSD 구조, 상태/저장 전략을 정리합니다.

**플랫폼:** pokit은 **iOS 전용** 앱이다. Android 앱 개발 및 크로스 플랫폼 대응은 **현재 계획에 없다**.

---

## 1. 제품 방향

### 1.1 목표

- 사용자가 하루 일과(`day-plan`)에서 **우선순위 순서로 카테고리·플로우를 정하고**, 그 순서대로만 진행한다.
- 시간표를 촘촘히 짜는 대신, **“오늘 무엇을 어떤 순서로 할지”**에 집중한다.
- **빠른 메모**로 즉석 아이디어·할 일을 줄 단위로 적고, 저장 시 오늘 플로우(및 필요 시 라이브 액티비티 등)에 반영할 수 있다.
- 각 태스크를 실제 실행 세션으로 전환해 진행도와 남은 시간을 확인한다.
- 실행 경험의 중심을 앱 내부 `activity-session` 화면에 둔다.
- 서버 없이 로컬 저장소 기반으로 안정적으로 동작하는 개인 플로우 도구를 지향한다.

### 1.2 현재 스코프

- **핵심 포함**
  - **우선순위 모드**: Day Plan에서 카테고리/플로우 순서만 정하고 진행
  - **하루 시작·마무리**: 집중 구간 시각 설정(설정·온보딩·데이플랜), 저장은 `HH:mm`, UI는 한글 시계 표기로 통일
  - **빠른 메모**: 짧은 입력으로 플로우 생성·저장 및 연동
  - 세션 시작/일시정지/재개/완료
  - 진행도, 남은 시간, 다음 태스크 반영
  - 설정 페이지와 카테고리별 목표 상세 설정
- **현재 제외(제품 핵심으로 두지 않음)**
  - Live Activity를 제품 핵심 경험으로 강제하는 요구사항
- **플랫폼 범위 밖**
  - Android 앱·잠금화면 등 비 iOS 플랫폼 (개발 계획 없음)

## 2. 핵심 사용자 시나리오

### 2.1 오늘 일과 구성(우선순위)

1. 사용자는 `day-plan` 화면에서 **우선순위 모드**를 켠다.
2. 오늘 진행할 **카테고리(플로우) 순서**를 정한다. 시간대별로 타임라인을 채우지 않아도 된다.
3. 필요 시 카테고리별 목표 상세를 연다.
4. 저장 후 오늘 일과가 즉시 반영된다.

### 2.1.1 하루 시작·마무리(집중 구간)

- 우선순위 데이플랜은 **하루 시작·마무리 시각**으로 오늘 집중 구간을 둘러싼다. 사용자는 **설정 → 시작·마무리** 또는 온보딩·데이플랜 진입 흐름에서 이 시각을 정한다.
- **저장 형식**은 `HH:mm` 문자열(24시간제, 당일 끝은 `24:00`)로 통일한다.
- **화면 표기**는 iOS 시간 피커(12시간제)와 인지가 맞도록 **오전/오후·12시간제 한글**로 보여 준다(설정 한 줄, 에디터의 시각 pill, 자주 쓰는 패턴 칩 등 동일 규칙). `24:00` 종료는 집중 구간 문맥에 맞춰 **자정·당일 마감** 의미로 한 줄에 드러낸다.

### 2.2 빠른 메모

1. 사용자는 같은 화면에서 **빠른 메모** 모드로 전환한다.
2. 줄 단위로 생각·할 일을 적는다.
3. **메모 저장**으로 오늘 플로우 블록으로 반영한다(내부적으로는 세션·알림 등과 연동될 수 있음).
4. 잠금 화면 등 외부 표시가 켜져 있으면 해당 채널에도 반영될 수 있다.

### 2.3 세션 실행

1. 사용자는 오늘 일과에서 **현재 우선 태스크**를 시작한다.
2. `activity-session` 화면에서 현재 플로우, 남은 시간, 진행도를 확인한다.
3. 필요 시 일시정지/재개/완료/건너뛰기를 수행한다.
4. 상태 변경은 도메인 스토어를 기준으로 즉시 동기화된다.
5. 태스크 완료 시 다음 우선 태스크 또는 종료 상태로 전환된다.

### 2.4 목표 상세 설정

1. 사용자는 카테고리별 목표 상세 설정 화면으로 진입한다.
2. 카테고리 특화 옵션(예: 물, 독서, 복약 등)을 조정한다.
3. 저장 시 해당 목표 설정이 Day Plan/세션 표시 규칙에 반영된다.
4. 설정 완료 후 필요하면 `flow-review` 화면에서 검토·시작으로 이어진다.

## 3. 도메인 모델

핵심 타입과 규칙은 `src/entities`에서 관리한다.

- `DayPlan`
  - 하루 일과의 기준 엔티티
  - **우선순위 순서**, 연결된 카테고리/블록, (구현에 따라) 날짜·요약 정보 포함
  - 우선순위 모드와 함께 **집중 구간(하루 시작·마무리 시각)** 이 붙을 수 있으며, 알림·타임라인·표시 문구에 반영된다.
- `DayPlanBlock` (또는 동등 개념)
  - 실행 단위(플로우 한 덩어리)
  - **우선순위 모드**에서는 사용자가 정한 순서가 진행 순서의 기준이 된다.
  - **빠른 메모** 출처(`blockOrigin: quickMemo` 등)로 생성된 블록은 동일 엔티티로 취급할 수 있다.
  - 세션·알림·표시를 위해 시작/종료 시각 등이 붙을 수 있으나, **기획상 사용자의 1차 입력은 “시간대 채우기”가 아니라 순서·메모 중심**이다.
- `Session` 관련 상태
  - 실행 중 여부, 일시정지 상태, 진행률, 남은 시간 계산 정보
  - `dayPlanRuntimeStore`에서 관리
- `History`
  - 일별 집중 시간·완료 수·카테고리 분포, 배지/마일스톤
  - 통계 화면(`day-plan-statistics`)의 데이터 원천
- `GoalCategory` 설정
  - 카테고리별 UI/행동 규칙(물, 독서, 복약, 금식, 기타 등)
  - 목표 상세는 `*Settings.tsx` 설정 UI만 제공(미리보기 UI 없음)

도메인 로직은 React 컴포넌트와 분리하고, 가능한 한 순수 함수/스토어 액션 중심으로 유지한다.

**제거된 레거시:** `Routine` / `RoutineExecution` 엔티티, `dayPlanStatsHistory`, Discover/Routines/Today 대시보드 플로우는 현재 코드베이스에 없다.

## 4. 아키텍처 원칙 (FSD)

### 4.1 레이어

pokit은 아래 레이어를 따른다.

- `src/application` (app 레이어)
- `src/pages`
- `src/widgets`
- `src/features`
- `src/entities`
- `src/shared`

의존성은 상위 레이어에서 하위 레이어로만 허용한다.

### 4.2 책임 분리

- `application`
  - 앱 부트스트랩, 전역 하이드레이션, 전역 연결 로직
- `pages`
  - 라우트 단위 화면 배선 및 조합
- `widgets`
  - 여러 feature/entity를 조합한 화면 블록
- `features`
  - 유즈케이스 단위 동작(세션 제어, 라이브 액티비티 동기화, 알림 스케줄링 등)
- `entities`
  - 도메인 타입, 규칙, 스토어, 계산 로직
- `shared`
  - 범용 UI, 유틸, 저장소 래퍼, 테마

### 4.3 네이밍/구조 규칙

- 세그먼트는 `ui`, `model`, `lib`, `api`, `config` 중심으로 구성한다.
- 같은 레이어 내 서로 다른 슬라이스 직접 import를 피한다.
- 공통화가 필요하면 `entities` 또는 `shared`로 승격한다.

### 4.4 현재 코드베이스 스냅샷 (2025-05 기준)

**Expo Router (`app/`)**

| 구분 | 라우트 | 페이지 |
|------|--------|--------|
| 탭 | `day-plan`, `priority-catalog`, `day-plan-statistics`, `settings` | `@pages/day-plan`, `@pages/settings` 등 |
| 스택 | `activity-session`, `goal-detail-settings`, `flow-review`, `widget-settings`, `daily-rhythm-settings`, `goal-detail-incomplete-reminder-settings` | 각 `@pages/*` |

**features (6)**

- `day-plan-notifications`, `category-reminder-notifications`, `local-notifications`, `other-category-resolve`, `live-activity-sync`(레거시)

**widgets (2)**

- `day-plan-priority-order`, `daily-rhythm-time-field`

**entities 스토어**

- `dayPlanStore`, `dayPlanDraftStore`, `dayPlanRuntimeStore`, `historyStore`, `localNotificationsStore`

## 5. 상태 관리 (Zustand)

### 5.1 원칙

- 여러 화면에서 공유되는 상태는 zustand 스토어를 사용한다.
- 비즈니스 로직은 컴포넌트보다 스토어 액션/셀렉터에 둔다.
- 시간·진행 표시는 가능한 한 **절대 시각·도메인 상태** 기반 계산을 우선한다.

### 5.2 스토어 위치

- 도메인 전역 상태: `src/entities/<domain>/model/*Store.ts`
  - `day-plan`: `dayPlanStore`, `dayPlanDraftStore`, `dayPlanRuntimeStore`
  - `history`: `historyStore`
  - `local-notifications`: `localNotificationsStore`
- 기능 전용 상태: `src/features/<feature>/model/*Store.ts` (현재는 feature 전용 zustand 스토어 없음)

### 5.3 상태 전이 규칙

- 세션 이벤트(`start/pause/resume/finish/skip`)는 도메인 상태를 먼저 갱신한다.
- 화면은 스토어 상태를 구독해 렌더링만 담당한다.
- 앱 재진입 시 저장된 상태를 기준으로 세션을 복원한다.

## 6. 데이터 영속화 (LocalStorage)

### 6.1 기본 전략

- LocalStorage를 1차 저장소로 사용한다.
- 스토어가 단일 진실 원천(SSOT)이며, 저장소는 영속화 계층 역할만 수행한다.
- 컴포넌트에서 `localStorage`를 직접 호출하지 않는다.

### 6.2 저장 모듈

- 공용 저장소 모듈: `src/shared/lib/storage`
- 도메인별 로드/세이브 헬퍼를 통해 타입 안정성을 유지한다.

### 6.3 키 원칙

- `pokit:*` 네임스페이스를 사용한다.
- 주요 키: `pokit:day-plan`, `pokit:day-plan-draft`, `pokit:history-daily-stats`, `pokit:history-achievements`, `pokit:history-meta`, `pokit:goal-detail-settings`, `pokit:settings` (전체 목록은 `src/shared/lib/storage/storageKeys.ts` 참고)
- 저장 구조는 엔티티 타입과 동일한 형태를 유지한다.
- `lockflow:*` → `pokit:*` 1회 마이그레이션은 `migrateLegacyStorageKeys`로 처리한다.

## 7. UX/카피 원칙

### 7.1 사용자 대면 문구

- 앱 이름 `POKIT`을 제외한 UI 문구는 한글을 기본으로 사용한다.
- 사용자 대면 용어는 `플로우`를 기본 용어로 통일한다.

### 7.2 화면 디자인

- **디자인 컨셉·토큰 문서:** [`docs/design/DESIGN_CONCEPT.md`](docs/design/DESIGN_CONCEPT.md) (레트로 시티팝 / Flat Brutalism Lite), [`docs/design/city-pop-minimalist.md`](docs/design/city-pop-minimalist.md) (색·타이포·간격). 코드: `src/shared/config/retroFlat.ts`.
- 카드 기반 레이아웃으로 현재 상태를 빠르게 파악할 수 있게 구성한다.
- 진행 정보는 프로그레스 바와 수치 텍스트를 함께 제공한다.
- 목표 상세 설정 화면 배경은 단순 평면 구성으로 유지하고 과한 장식 요소는 피한다.

#### 7.2.1 하단 탭(메인 내비게이션)

- 탭은 **라벨 없이 아이콘**만 사용한다(오늘·담기·설정 등, 제품에서 정한 매핑 유지).
- **선택된 탭**: 연한 회색 면, **1px 검정 테두리**, 아이콘은 검정에 가깝게.
- **비선택 탭**: 흰(또는 다크 모드에서의 동등 면), **연한 회색 테두리**, 아이콘은 중간 회색.
- 각 탭은 **둥근 직사각형(pill에 가까운 코너 반경)** 으로 구분되며, 탭 사이는 좁은 간격으로 배치한다.
- 가운데 **집중/저장 등 문구형 primary 버튼**은 탭 pill과 별도 스타일(기존 primary 강조)로 둔다.

#### 7.2.2 시각(시계) 표기

- 저장·검증·스케줄 계산은 **24시간제 `HH:mm`** 을 기준으로 한다.
- 사용자에게 보이는 고정 시각(설정 요약, 하루 시작·마무리 에디터, 타임라인 한 줄 등)은 **`formatMinuteOfDayKo` / `formatHhmmClockKo` 와 같은 도메인 규칙**으로 한글 오전·오후를 붙여 일관되게 표시한다.

## 8. 기술/개발 운영 메모

### 8.1 플랫폼

- 제품·스토어·빌드 파이프라인은 **iOS를 전제**로 한다.
- 저장소에 `android/` 등이 남아 있어도 **우선 지원 대상이 아니며**, Android 전용 기능이나 동등 UX를 맞추는 작업은 범위에 넣지 않는다.

### 8.2 Expo CLI 정책

- 에이전트는 사용자 명시 요청 없이 Expo CLI 명령을 실행하지 않는다.
- `expo prebuild`는 영향도가 크므로 기본적으로 자동 실행하지 않는다.

### 8.3 iOS 실행 주의

- Xcode 실행 스킴은 일반 개발 시 `Pokit`(메인 앱)를 사용한다.
- `PokitLiveActivity` 스킴은 확장 디버깅 목적일 때만 사용한다.

## 9. 확장 로드맵

- 우선순위 일과와 빠른 메모 연동 흐름 고도화(저장 후 경험, 요약 표시)
- 세션 완료 기록 기반 회고/통계 화면 강화
- 알림 품질 개선(시작 전 리마인드, 미완료 후 후속 안내)
