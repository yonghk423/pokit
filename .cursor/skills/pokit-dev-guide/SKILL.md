## 작업 흐름

1. 요청이 주인공·장면·일기, 오늘의 메이트, 기록·설정 중 어디에 속하는지 확인합니다. 보류 기능은 플래그와 실제 진입점을 확인합니다.
2. 기존 타입·상태·저장 함수를 읽고 수정 범위를 정합니다. 내부 식별자는 보존합니다.
3. 화면의 일회성 상태와 공유 도메인 상태를 구분합니다. 로컬 상태로 충분한 폼에 새 전역 스토어를 만들지 않습니다.
4. 기존 저장 경로를 사용하고 새 일기 초안과 기존 일기 데이터를 분리합니다.
5. 종이·만년필 디자인, 입력, 접근성, 카드 모션과 튜토리얼의 직접 조작을 함께 확인합니다.
6. 관련 검사를 실행하고 변경 내용과 확인 범위를 간결하게 설명합니다.

## 위치 선택

- 도메인 규칙·타입·파생 값: `src/entities`
- 기능과 유즈케이스: `src/features`
- 복합 UI: `src/widgets`
- 화면과 탐색 조립: `src/pages`, 루트 `app/`
- 전역 초기화: `src/application`
- 공용 UI·저장·번역·설정: `src/shared`

화면·소스·저장 데이터의 존재만으로 해당 기능이 공개되어 있다고 판단하지 않습니다. 날씨·공지·구독 같은 외부 서비스는 실제 구현 범위를 확인하고, 검증되지 않은 기기 간 동기화나 결제를 제품 기능으로 약속하지 않습니다.

Expo CLI와 네이티브 재생성은 프로젝트 규칙의 사용자 허가 범위를 따릅니다. 이미 승인된 작업에 대해 같은 확인을 반복하지 않습니다.
